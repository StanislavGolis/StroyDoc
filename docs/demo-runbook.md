# Демо-рунбук «СтройДок» (сценарий для показа)

> Время: 15–20 минут. Роли: демонстратор (Руководитель ПТО / админ), зрители.
> Окружение: docker-compose запущен, БД `stroydoc`, логин `admin@example.com / admin123`.
> Файлы-образцы лежат локально в `docs/` (в git не хранятся): `Спецификация ТСО.pdf`, `Спецификация КЖ.pdf`, `Спецификация ЭМ.pdf`, `Пример-Паспорта ТСО.pdf`.

## Подготовка (за 30 минут до показа)
1. `docker compose up -d --build` — все сервисы healthy.
2. `docker compose run --rm api alembic upgrade head` (если новые миграции).
3. Проверить вход `admin@example.com`.
4. Убедиться, что на экране 1920x1080, браузер без зума.
5. (Опция) бэкап БД: `docker compose exec db pg_dump -U stroydoc stroydoc > demo_backup.sql`.

## Сценарий

### 1. Дашборд руководителя (2 мин)
- Открыть http://localhost:3000 → меню «Дашборд».
- Показать карточки статистики, теги актов/паспортов, карточки объектов.
- На карточке объекта — 4 полосы прогресса: АВК, АОСР, ВСО (материалы+оборудование) и ВР (работы).
- Карточки можно перетаскивать за любое место — они встают на ячейки размеченной сетки (клик по карточке в объект не переводит).

### 2. Новый объект (3 мин)
- Меню «Объекты» → «Создать объект»: название «Демо: Реконструкция ИТСО», шифр `00819-ДЕМО`, статус «В работе».
- Перейти в объект → вкладки по порядку (Файлы, Документы, Позиции, Контрольная таблица, Акты).

### 3. Загрузка РД и парсинг (5 мин)
- Вкладка «Файлы» → вид «Спецификация РД» → загрузить `Спецификация ТСО.pdf` (1,2 МБ) → «Распарсить» → «Разобрано позиций: 372 (в т.ч. 15 работ из ведомости объемов работ)».
- Повторить для `КЖ` (23, работы 16) и `ЭМ` (40, работы 11).

### 4. Мастер-список (3 мин)
- Вкладка «Позиции (РД)»: плашки шифров свёрнуты → раскрыть ТСО.
- Поправить наименование двойным кликом; включить «Объединить одинаковое оборудование» (сумма количества).
- Тип позиции виден в колонке «Тип» и правится там же (материал / оборудование / работа).
- Фильтр по типу позиции; в шапке шифра поле «Тип для нетипизированных» массово проставляет тип.
- Фильтр «Скрытые»/«Отслеживаем».

### 5. Документы и Контрольная таблица (4 мин)
- «Документы (паспорта)» → загрузить небольшой PDF-паспорт (или файл из архива) с номером → «Привязать позиции» → выбрать несколько строк.
- «Контрольная таблица»: у выбранных строк колонка «Паспорт/Сертификат» зелёная; фильтр «Без паспорта» показывает остальные.
- Показать матрицу закрытия: у материала ВР — серая «не требуется», у работы серые Паспорт/АВК/АОСР/ВСО; фильтр по типу позиции.

### 6. Акты и DOCX (3 мин)
- «Акты» → «+ Создать акт» → тип «Акт входного контроля» (номер можно не вводить — подставится автоматически). В списке только материалы и оборудование; отметить позиции → «Создать».
- Затем тип «Ведомость выполненных работ»: в списке только работы — показать, что материалы в ВР не предлагаются (умный фильтр по типу).
- Статус «Черновик» → «Готов» (клик по бейджу).
- «DOCX» — скачивается файл; открыть и показать таблицу.

### 7. Финал (1 мин)
- Вернуться на «Дашборд»: объект «Демо…» с прогрессом, «Актов: N»; показать, что риск снизился.

## Если что-то падает
- Логи: `docker compose logs -f api`, `docker compose logs -f frontend`.
- Обновить данные: `docker compose restart api frontend`.
- Сбросить демо: создать новый объект (вместо повторного использования).

## Проверка перед показом (чек-лист)
- [ ] Вход под admin работает.
- [ ] Дашборд открывается и показывает объекты.
- [ ] Загрузка ТСО/КЖ/ЭМ и парсинг проходят (372 / 23 / 40 позиций).
- [ ] Привязка паспорта меняет статус в Контрольной таблице.
- [ ] Матрица закрытия: у материала ВР серый («не требуется»), у работы — Паспорт/АВК/АОСР/ВСО.
- [ ] Акты: АВК — материалы+оборудование, АОСР — материалы, ВСО — оборудование, ВР — работы (материалы в ВР не предлагаются).
- [ ] Акт создаётся, статус переключается, DOCX скачивается.

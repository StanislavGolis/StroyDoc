ДИЗАЙН-СИСТЕМА «Бинго-Док»
Версия 1.0 (UI/UX Guidelines)
1. Глобальная архитектура экрана (Layout)
Ты правильно выбрал Layout с левым сайдбаром. Это стандарт для B2B-систем (как в Битрикс24 или Jira).

text
+------------------+--------------------------------------------------+
|   🏗 БИНГО-ДОК    |  Хлебные крошки: Объект → Позиции                 |
|                   |                                                  |
|  [Объекты]        |  +-------+  +-----------------------------------+ |
|  ───────────────  |  |       |  |  Заголовок страницы     | |
|  Газпром КС-15    |  |       |  |  (Действия: Экспорт)  | |
|  Котельная №3     |  |       |  +-----------------------------------+ |
|  Школа в Зеленом  |  |       |  |                                   | |
|                   |  |       |  |   ОСНОВНОЙ КОНТЕНТ               | |
|  [Пользователи]   |  |       |  |   (Таблицы, карточки, формы)     | |
|  [Настройки]      |  |       |  |                                   | |
|                   |  |       |  |                                   | |
|  👤 Иванов И.И.   |  +-------+  +-----------------------------------+ |
+------------------+--------------------------------------------------+
Правила:

Сайдбар (ширина 240px): Темный фон (например, #1e293b). Белый текст. Активный пункт меню подсвечивается (например, синим #3b82f6).

Хлебные крошки (Breadcrumbs): Показывают путь: Объекты → Газпром КС-15 → Позиции. Это помогает не теряться.

Верхняя панель (Toolbar): Здесь кнопки действий для текущей вкладки («+ Создать акт», «Экспорт в Excel», «Загрузить файл»).

2. Цветовая палитра (Статусы — главное)
В твоей системе главное — это статусы. Они должны бросаться в глаза мгновенно.

Назначение	Цвет	HEX	Где используется
Успех / Готово	Зеленый	#22c55e	Паспорт привязан, акт подписан.
Предупреждение / В процессе	Желтый/Оранжевый	#eab308	Акт в черновике, позиция ожидает подтверждения.
Ошибка / Критично	Красный	#ef4444	Нет паспорта, расхождение не разрешено.
Не требуется	Серый	#94a3b8	Для этого типа работ акт не нужен.
Акцент (Кнопки)	Синий	#3b82f6	Все основные действия (Сохранить, Создать, Привязать).
Фон карточек	Белый/Светло-серый	#f8fafc	Для карточек объектов и модальных окон.
Важно: Никогда не используй красный для кнопок "Сохранить" — только для "Удалить".

3. Типографика (Чтобы не пестрело)
Используй системные шрифты без засечек (санс-сериф). Они быстрее загружаются и привычнее для глаз.

css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
Элемент	Размер	Начертание	Где
Название объекта	24px	Bold (жирный)	Вверху страницы.
Заголовок вкладки	20px	Semi-bold	Под хлебными крошками.
Название таблицы	16px	Medium	Шапка таблицы.
Текст в таблице	14px	Regular	Основные данные.
Мелкий текст	12px	Regular	Подписи, даты, ID.
4. Сетка и отступы (Дышите воздухом)
B2B-системы любят плотность, но она не должна превращаться в кашу.

Поля страницы: 24px от края экрана.

Отступ между вкладками: 8px (горизонтально).

Отступ между строками в таблице: 12px (padding внутри ячеек).

Карточки объектов: Ширина ~300px, между ними 16px. Перенос по сетке (Grid).

5. Компоненты (Из чего строим страницы)
5.1. Таблицы (Самая важная часть)
Таблица в «Позициях» и «Бинго-карте» — это сердце продукта.

Шапка: Темный фон (#f1f5f9), жирный текст.

Строки: Чередование белого и очень светлого серого (#f8fafc), чтобы глаз не уставал.

Колонка с действиями: Всегда крайняя справа. Там иконки (карандаш ✏️ — редактировать, корзина 🗑️ — удалить).

Статусы в таблице: Делай их в виде круглых бейджей (Pill/Badge) рядом с текстом, а не заливкой всей ячейки. Например: [🟢 Привязан].

5.2. Формы (Выпадающие списки)
Ты правильно решил делать выбор через выпадающие списки (Dropdown).

Правило: Если вариантов мало (до 5) — используй Radio-кнопки или переключатели.

Если вариантов много (РД vs Смета): Используй Select (ComboBox) с поиском.

Модальное окно: При создании акта (выбор позиций) используй большое модальное окно на 80% экрана, чтобы было видно много строк.

5.3. Карточка объекта (На главной)
Каждый объект в списке — это карточка.

6. Сценарии навигации (Как пользователь двигается)
Попадание в систему:

Руководитель видит Дашборд (карточки объектов + сводка).

Инженер видит список объектов, куда он назначен.

Работа с объектом:

Нажимает на карточку объекта → попадает на вкладку «Информация» (по умолчанию).

Переключает вкладки:

Информация → смотрит общие данные.

Назначения → (только для руководителя) добавляет инженеров.

Файлы → загружает РД и Смету.

Документы → загружает паспорта.

Позиции → правит Мастер-список (ручная правка).

Бинго-карта → смотрит статусы (здесь он живет 80% времени).

Акты → создает новые акты.

Создание акта:

На вкладке «Акты» нажимает «+ Создать».

Открывается модалка с выбором типа и чекбоксами позиций.

Нажимает «Сформировать» → скачивается файл.

7. Адаптивность (Desktop-First)
Пока не парься о телефонах. Твоя целевая аудитория — инженеры за компьютерами с большими мониторами (1920x1080).
Но минимальная ширина, которую ты должен поддерживать — 1280px (чтобы таблица не ломалась).

8. Иконки (Бесплатно и сердито)
Используй Lucide Icons (они легче и красивее FontAwesome) или Heroicons (от создателей Tailwind).

Основные иконки для сайдбара:

🏗 Объекты (Building2)

👥 Пользователи (Users)

📄 Файлы (FileText)

📑 Документы (FolderOpen)

📊 Позиции (ListChecks)

🎯 Бинго (Target)

📋 Акты (ClipboardList)

9. Техническая реализация (FastAPI + React)
Чтобы дизайн не развалился при разработке, я рекомендую тебе:

На бэкенде: Отдавай статусы в виде четких Enum (например, status: "ready" | "warning" | "danger").

На фронтенде: Создай компонент <StatusBadge status={row.status} />, который сам подставит цвет и текст.

Не используй сложные CSS-фреймворки, возьми чистый Tailwind CSS — он позволит быстро верстать, не отвлекаясь на CSS-классы.

## Цель (скорректированный старт)

Смета от заказчика ещё не получена, поэтому первая часть спринта сфокусирована на двух
самостоятельных блоках, которые можно проверить на уже имеющихся образцах:

1. **Загрузчик файлов объекта** (объектное хранилище, лимиты, привязка к объекту) — на образце
   «Пример-Паспорта ТСО.pdf» (58 МБ, 365 стр. сканов) проверяются лимиты и потоковая загрузка.
2. **Парсер PDF-спецификаций** (текстовый слой) — на образце «Пример Спецификация из РД.pdf»
   (69 стр., векторный текст) — самая рискованная часть MVP, снимаем её первой.

Когда появятся образцы сметы (.xml АРПС / .xlsx) — добавим нормализацию сметы и «сведение» в Спринте 3.

## Образцы файлов

| Файл | Размер | Роль |
|------|--------|------|
| `docs/Пример Спецификация из РД.pdf` | 1,2 МБ, 69 стр. | текст → парсер таблиц |
| `docs/Пример-Паспорта ТСО.pdf` | 58 МБ, 365 стр. | сканы → лимиты загрузчика (превышает 50 МБ!) |

**Правило:** реальные файлы НЕ коммитим (конфиденциально, большие). Кладём в `samples/` + `.gitignore`.
В git — только обезличенные мини-фрагменты для автотестов (`backend/tests/fixtures/`).

## Ограничения MVP (действуют)
- Поштучно до **100 МБ** (образец 58 МБ); ZIP-архивы паспортов до 1 ГБ; квота объекта 10 ГБ.
- Разрешённые типы по виду документа: спецификация — `pdf, xlsx`; смета — `xml, xlsx`; паспорта — `pdf, zip`.
- Парсинг пока синхронный в запросе (69 стр. парсятся быстро); перенос в Celery — по мере роста.

## Definition of Done
- [x] Админ/инженер загружает PDF (в т.ч. 58 МБ) → файл в хранилище, метаданные в БД, sha256.
- [x] Повторная загрузка того же файла → 409 (дубликат).
- [x] Файл недопустимого типа / сломанный → 400.
- [x] Запуск парсинга спецификации → позиции с колонками (поз., наименование, марка/ТУ, ед., кол.) в БД.
- [x] Водяные знаки PDF-XChange не попадают в позиции.
- [x] Вкладки «Файлы» и «Позиции» работают в UI; автотесты зелёные; ruff чист.

## Проверка на реальном образце
- Загружен «Пример Спецификация из РД.pdf» (1,2 МБ) → файл в MinIO, sha256 записан.
- `POST /parse` → **357 позиций** извлечено и сохранено в `source_item`.
- Результат отдаётся через `GET /objects/1/items` и виден во вкладке «Позиции (РД)».
- Качество MVP-парсера: поля «как в документе», многострочные ячейки местами разъезжаются между колонками — ожидаемое ограничение, будет улучшаться по мере образцов.

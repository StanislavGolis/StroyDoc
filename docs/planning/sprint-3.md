# Спринт 3 — Полировка перед демо

> Статус: план (черновик). Дата: 09.09.2026. База: README (ТЗ v1.1), DESIGN.md, docs/planning/sprint-1..2.
> Оценка: **3–5 рабочих дней** (1–2 разработчика).

## 1. Цель

Стабильная демо-сессия на 15–20 минут по сквозному сценарию без падений и «каши» в UI:

```
Логин (руководитель) → Дашборд → Объект
→ Файлы (загрузка РД ТСО/КЖ/ЭМ, парсинг) → Позиции (правка, объединение, шифр-плашки)
→ Документы (паспорта + привязка) → Акты (создание, DOCX) → Бинго-карта (статусы)
→ Дашборд (проценты/риски)
```

## 2. Принятые решения (заказчик)
1. **Ребрендинг: «СтройДок»** (русское название). Выполняется в этом спринте: UI, README/ТЗ, DESIGN.md, название API. Внутренние идентификаторы (`stroydoc`, docker, БД) не меняем.
2. **E2E-смоук — ручной чек-лист** (Playwright не делаем).
3. **Демо — новый объект**: на сессии создаём чистый объект и на глазах загружаем файлы ТСО/КЖ/ЭМ (локально в `docs/`), парсим, привязываем паспорта, создаём акты.

## 3. Что НЕ входит (переносим в «нормальную версию»)
- Экспорт «Отсутствующие паспорта» в Excel и прочие выгрузки.
- OCR-автораспознавание реквизитов паспортов (по ТЗ опционально).
- Мультитенантный UI, ЭЦП, шаблоны актов с редактором.

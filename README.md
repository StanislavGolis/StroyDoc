# СтройДок — контроль комплектности документации для ПТО

> Система для отдела ПТО: собрать позиции из комплектов рабочей документации
> в единый мастер-список, проверить, что к каждой позиции приложены документы,
> и подготовить акты к приёмке.

**Статус: MVP в разработке.** Бэкенд реализован (44 эндпоинта, 8 миграций,
10 тестовых наборов), интерфейс закрывает объекты, разделы, позиции и документы;
экран конструктора актов — в работе. Проект не запущен в эксплуатацию.

---

## Задача, из-за которой это появилось

В ПТО комплектность ведут в Excel: мастер-список по шифрам рабочей документации
(ТСО, КЖ, ЭМ, …), пул паспортов и сертификатов, контрольная таблица закрытия.
К приёмке всплывают незакрытые позиции — не потому что их забыли, а потому что
связь «позиция ↔ документ ↔ акт» держится в голове у инженера, а не в системе.

Отсюда три вещи, которые делает СтройДок:

1. **Мастер-список из РД.** Загрузка спецификаций (PDF), нормализация номенклатуры,
   разнесение позиций по шифрам объекта.
2. **Матрица закрытия.** Тип позиции (материал / оборудование / работа) определяет,
   какие акты для неё обязательны. Позиция считается закрытой, только когда
   приложены все документы и подписан нужный акт.
3. **Конструктор актов.** Генерация АВК, АОСР, ВСО, ВР с автоматической подстановкой
   привязанных документов.

**Сметы выведены за рамки MVP** осознанно: первичная работа и подписание у
стройконтроля идут по рабочей документации, а не по смете. Сведение «РД ↔ Смета» —
следующая версия.

## Что реализовано

| Слой | Состояние |
|---|---|
| **API** | 44 эндпоинта: объекты, разделы РД, позиции, документы, акты, файлы, дашборд, пользователи, авторизация |
| **БД** | 8 миграций Alembic: объекты и файлы, позиции источника, пул входящих документов, акты, рабочая область разделов РД, тип позиции, полная страница шифра |
| **Парсинг** | Разбор спецификаций PDF с нормализацией номенклатуры (креПёж, металлопрокат, инертные материалы…) |
| **Фронтенд** | Логин, дашборд, объекты, карточка объекта, пользователи |
| **Тесты** | 10 наборов: объекты, разделы, позиции, документы, файлы, акты, дашборд, авторизация, тип позиции |
| **Хранилище** | Абстракция `Storage`: локальная ФС для разработки, MinIO для контейнеров |

**В работе:** экран конструктора актов, визуальная контрольная таблица, сквозной
сценарий «загрузил спецификацию → разнёс по шифрам → увидел незакрытые позиции».

## Запуск

```bash
docker compose up --build
```

Бэкенд: `http://localhost:8000/docs` — OpenAPI со всеми 44 эндпоинтами.
Фронтенд: `http://localhost:3000`.

Демо-данные для входа заведены в `backend/seed_demo_data.py` (роли ПТО).

## Тесты

```bash
cd backend && pytest
```

## Доменная модель

| Сущность | Смысл |
|---|---|
| **Объект** | Строящийся объект, к которому привязаны шифры РД |
| **Шифр РД** | Комплект рабочей документации (ТСО, КЖ, ЭМ…); у узла их может быть несколько |
| **Позиция** | Строка мастер-списка: материал, оборудование или работа |
| **Документ** | Паспорт, сертификат, акт — привязывается к позиции |
| **Акт** | АВК, АОСР, ВСО, ВР — форма приёмки |
